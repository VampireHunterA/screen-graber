## 1. Целевой сценарий

```
Плитка в шторке
   │  (тап; при заблокированном экране — сначала unlockAndRun)
   ▼
Прозрачная CaptureActivity (без затемнения, без SYSTEM_ALERT_WINDOW)
   │  createScreenCaptureIntent()
   ▼
Системный диалог MediaProjection → «Начать сейчас» / отказ
   │  onActivityResult RESULT_OK
   ├─ отказ → finish(), ничего не остаётся
   ▼
Foreground service (type=mediaProjection) → getMediaProjection() → VirtualDisplay+ImageReader
   │  один кадр всего экрана (после сворачивания шторки и диалога)
   ▼
Экран выделения: «замороженный» кадр, лёгкое затемнение, надпись «Выделите область»
   │  протяжка прямоугольника → корректировка за 4 угла и 4 стороны → «Распознать»
   ▼
Обрезка Bitmap по прямоугольнику (координаты кадра = координаты экрана)
   ▼
OCR Tesseract: `rus+eng` одним проходом, офлайн
   ├─ пусто/ошибка/таймаут → сообщение, корректный выход (без зависания)
   ▼
Экран результата: текст + крупная кнопка «Копировать»
   │  ClipboardManager.setPrimaryClip()
   ▼
finish() → возврат в исходное приложение (оно было на паузе)
```

Почему не системный overlay: `SYSTEM_ALERT_WINDOW` — лишнее спецразрешение, а сам overlay попал бы
в скриншот; `FLAG_SECURE` на overlay сделал бы область чёрной. Прозрачная Activity + «замороженный»
кадр дают тот же визуальный результат (затемнение и рамка), не требуют лишних разрешений и
исключают расхождение координат из-за статус-бара, «чёлки» и навигационной панели.

## 3. Архитектура

Одна Activity-потоковая машина состояний, один foreground service, один кастомный View, OCR за
интерфейсом (чтобы движок можно было заменить без переписывания сценария).

```
CaptureTileService ──startActivityAndCollapse──▶ CaptureActivity
                                                   │
                    ProjectionService (FGS) ◀──────┤ startForeground / stopSelf
                    ScreenCapture (VirtualDisplay+ImageReader) ──▶ Bitmap кадра
                                                   │
                    SelectionView (рамка, маркеры) ──▶ Rect в координатах Bitmap
                                                   │
                    OcrEngine ◀── TesseractOcrEngine (rus+eng)
                                                   │
                    Результат + ClipboardManager ──▶ finish()
```

Состояния `CaptureActivity`: `CONSENT → CAPTURING → SELECTING → RECOGNIZING → RESULT → CLOSED`.
Переход в `CLOSED` возможен из любого состояния; он всегда освобождает projection, ImageReader,
VirtualDisplay, foreground service и уведомление.

Компоненты:

| Компонент | Ответственность |
|---|---|
| `CaptureTileService` | состояние плитки, обработка тапа, `unlockAndRun`, запуск Activity |
| `ProjectionService` | foreground service с типом `mediaProjection`, уведомление, остановка |
| `ScreenCapture` | создание projection/VirtualDisplay/ImageReader, чтение одного кадра с таймаутом, конвертация с учётом `rowStride`, освобождение |
| `CaptureActivity` | машина состояний, согласие, обрезка, OCR, результат, копирование, гарантированная очистка |
| `SelectionView` | рисование кадра и затемнения, создание/перенос/изменение рамки, маркеры, ограничения |
| `OcrEngine` / `TesseractOcrEngine` | инициализация `rus+eng`, распознавание, `recycle()` |
| `TessdataInstaller` | однократное копирование моделей из `assets/tessdata` в `filesDir/tessdata` |
| `MainActivity` | инструкция «как добавить плитку», проверка наличия моделей, диагностический экран |

## 5. Этапы реализации

Каждый шаг заканчивается проверкой; без неё шаг не считается выполненным.
Текущий статус: **шаг 1 выполнен**, шаги 2–10 не начаты.

**Шаг 1. Каркас проекта. — ВЫПОЛНЕН (этап 4).**
Gradle-файлы, wrapper, `app/build.gradle.kts`, `MainActivity` и тема.
Проверка: `./gradlew :app:assembleDebug` — **BUILD SUCCESSFUL** (33 задачи, 24 с, APK 2,3 МБ).
Доказательство: `docs/build-logs/assembleDebug-2026-10-27.txt`.

**Шаг 2. Манифест и плитка.**
`CaptureTileService` с иконкой и меткой, обработка `onStartListening`/`onClick`,
`unlockAndRun` при `isLocked()`, `startActivityAndCollapse` с `NEW_TASK|EXCLUDE_FROM_RECENTS`,
перехват исключений с понятным сообщением.
Проверка: плитка появляется в правке шторки; тап запускает Activity; панель сворачивается;
на заблокированном экране сначала запрашивается разблокировка.

**Шаг 3. MediaProjection и foreground service.**
`ProjectionService`, запрос согласия из Activity, обработка `RESULT_CANCELED` и `SecurityException`,
порядок «согласие → старт FGS → `getMediaProjection()`».
Проверка: согласие запрашивается при каждом запуске; отказ завершает сценарий без уведомления
и без сервиса.

**Шаг 4. Захват кадра.**
`ScreenCapture`: `ImageReader` (`RGBA_8888`, `maxImages=2`), `VirtualDisplay` на полном разрешении,
ожидание кадра с таймаутом ~2 с, конвертация с учётом `rowStride`, освобождение ресурсов в `finally`.
Задержка ~700–800 мс после `onActivityResult`, чтобы шторка и диалог успели исчезнуть; при пустом
кадре — до 3 попыток.
Проверка: получен кадр 1:1 без искажений и без элементов шторки/диалога.

**Шаг 5. Экран выделения.**
`SelectionView`: кадр как фон, затемнение вне рамки, надпись «Выделите область», протяжка
«угол → угол», затем 4 угла + 4 стороны, минимальный размер 24 dp, ограничение границами экрана,
перенос рамки, кнопки «Распознать» и «Отмена».
Проверка: рамка совпадает с содержимым под ней (отклонение ≤1 px), маркеры работают.

**Шаг 6. Обрезка и ориентация.**
`Bitmap.createBitmap(source, x, y, w, h)`, фиксация ориентации на сеанс, освобождение исходного
Bitmap после обрезки.
Проверка: в OCR уходит ровно выделенная область.

**Шаг 7. Модели и OCR.**
`TessdataInstaller` (копирование ~29,3 МБ в `filesDir/tessdata`, идемпотентно, в фоне с индикатором),
`TesseractOcrEngine` (`rus+eng`, upscale ×2 при мелком тексте, `psm` — константа для экспериментов,
`recycle()` в `finally`), вызов в `Dispatchers.Default`.
Проверка: смешанная строка распознаётся без переключения языка; повторный запуск не копирует модели.

**Шаг 8. Результат и буфер обмена.**
Экран с текстом (прокрутка) и крупной кнопкой «Копировать», `ClipboardManager.setPrimaryClip`,
собственный короткий индикатор (на Android 11 системного тоста нет), `finish()`.
Проверка: вставка в другом приложении даёт тот же текст.

**Шаг 9. Краевые случаи и очистка.**
Единый `try/finally` + `finishAndRemoveTask()`, `MediaProjection.Callback.onStop`, обработка
повторного тапа по плитке во время сеанса (`singleTask`), `onStop`/`onDestroy`.
Проверка: после каждого сценария нет остаточных окон, сервисов и уведомлений.

**Шаг 10. Тесты, сборка, приёмка.**
JVM-тесты геометрии, `assembleDebug`/`assembleRelease`, прогон матрицы проверок на Mi 9T,
сбор доказательств (logcat, dumpsys, aapt), обновление `PROJECT_STATUS.md`.

## 6. Обработка отмены, ошибок и таймаутов

| Ситуация | Поведение | Что должно остаться после |
|---|---|---|
| Пользователь отказался от захвата (`RESULT_CANCELED`) | `finishAndRemoveTask()`, без сообщений об ошибке | ничего: ни окна, ни сервиса, ни уведомления |
| Нажата «Отмена» / Back на выделении или результате | освободить Bitmap, `finishAndRemoveTask()` | исходное приложение на экране |
| Кадр не получен за ~2 с | до 3 попыток, затем сообщение «Не удалось снять экран» и выход | ресурсы освобождены |
| В кадре ещё видна шторка/диалог | повторный захват после задержки | — |
| OCR вернул пустой/пробельный текст | сообщение «Текст не найден» + кнопки «Повторить»/«Закрыть» | без зависания |
| Исключение OCR / нехватка памяти | сообщение об ошибке, `recycle()`, выход | без утечек |
| Защищённое окно (`FLAG_SECURE`) | кадр чёрный → пустой OCR → штатное сообщение | без падения |
| Повторный тап по плитке во время сеанса | `singleTask` переиспользует Activity; повторный запрос согласия не плодит окна | один сеанс |
| Поворот экрана во время сеанса | ориентация фиксируется на сеанс; при смене — корректное завершение | без «сломанных» координат |
| `MediaProjection.Callback.onStop` (система остановила захват) | немедленная очистка и выход | без утечки |
| `SecurityException` при `getMediaProjection()` | сообщение и выход | FGS остановлен |

Общее правило: любое завершение проходит через один метод `finishSession()`, который идемпотентно
освобождает projection, VirtualDisplay, ImageReader, Bitmap, останавливает FGS и убирает уведомление.

## 7. Проверки на устройстве (Xiaomi Mi 9T, Android 11 / MIUI 12)

Проверки выполняются вручную на устройстве; без них соответствующий пункт не считается выполненным.

### 7.1 Плитка MIUI
- Плитка появляется в правке шторки/«Центра управления» MIUI и перетаскивается в активные.
- Тап запускает захват, панель сворачивается.
- Поведение после перезагрузки (известны случаи, когда сторонние плитки «сереют» — фиксируем факт).
- Поведение на заблокированном экране: сначала разблокировка, затем захват.
- Повторный тап во время активного сеанса не создаёт второй экземпляр Activity.

### 7.2 Согласие MediaProjection
- Диалог появляется **при каждом** запуске, текст системный.
- «Отмена» → мгновенный выход, нет уведомления, нет сервиса.
- «Начать сейчас» → захват, уведомление FGS видно только короткое время и исчезает после кадра.
- Проверка через `dumpsys activity services` — сервис отсутствует после завершения.

### 7.3 Координаты выделения
- Наложить на экран эталонную сетку/линейку, выделить известный элемент, сравнить обрезку.
- Проверить края у статус-бара, «чёлки», навигационной панели и по всем четырём углам.
- Проверить изменение размера за каждый из 8 маркеров и перенос рамки.
- Проверить минимальный размер и выход за границы.

### 7.4 OCR
- Три блока: только русский, только английский, смешанный (например,
  «Открой Settings → Wi-Fi и нажми Сохранить»).
- Мелкий текст (12–14 sp), крупный заголовок, текст на цветном фоне.
- Авиарежим: результат не меняется; `aapt dump permissions` не содержит `INTERNET`.
- Замер времени распознавания (секундомер) — фиксируется как измерение, а не оценка.
- Проверить порядок языков `rus+eng` и `eng+rus` (влияет на результат по документации).

### 7.5 Буфер обмена
- «Копировать» → выход → вставка в другом приложении (заметки/мессенджер) → текст совпадает.
- Проверить многострочный текст и пустые строки.
- Проверить, что кнопка доступна сразу после OCR и не требует повторного нажатия.

### 7.6 Повторные запуски и очистка
- 5 запусков подряд, включая отмены на разных шагах.
- Проверить отсутствие остаточных окон: `dumpsys window windows | grep -i screengraber`.
- Проверить отсутствие сервиса: `dumpsys activity services | grep screengraber`.
- Проверить, что после выхода активен тот же экран исходного приложения.
- Проверить `logcat` на `FATAL EXCEPTION`, `SecurityException`, `TransactionTooLargeException`.

| MIUI блокирует запуск Activity из плитки | Высокое | `startActivityAndCollapse`, `unlockAndRun`, диагностика в `MainActivity`, проверка переключателя MIUI пользователем | тест на устройстве |
| В кадр попадает анимация шторки или диалога согласия | Среднее | задержка 700–800 мс, до 3 попыток захвата | сравнение кадра с эталоном |
| Прозрачная Activity на MIUI показывает чёрный фон | Высокое | прозрачная тема без preview, проверка до реализации выбора рамки | тест на устройстве |
| Низкая точность Tesseract на мелком тексте и омоглифах (`С/C`, `Р/P`, `А/A`) | Среднее | upscale ×2, подбор `psm`, `tessdata_best`, отключение словарей при необходимости; запасной путь — PP-OCR (отдельный PoC) | эталонный набор строк, подсчёт ошибок |
| Защищённые окна дают чёрный кадр | Среднее | штатное сообщение «Текст не найден» | тест в банковском приложении |
| Утечка projection/FGS/Bitmap при исключении | Среднее | единый `finishSession()` в `finally`, `onStop` callback | `dumpsys` + `logcat` |
| Поворот экрана ломает координаты | Низкое | фиксация ориентации на сеанс | тест |
| Модели 29,3 МБ дублируются в APK и в `filesDir` | Низкое | однократное копирование, проверка по размеру; при нехватке места — сообщение | установка на устройство |
| `targetSdk 30` не подходит для Google Play | Низкое (публикация не нужна) | sideload; при необходимости позже `targetSdk 34` (+`POST_NOTIFICATIONS`, `FOREGROUND_SERVICE_MEDIA_PROJECTION`) | решение до реализации |

### 9.2 Открытые вопросы (не считать решёнными до тестирования)

1. Не блокирует ли MIUI 12 запуск Activity из плитки и как ведёт себя плитка после перезагрузки.
2. Успевает ли шторка и системный диалог полностью исчезнуть за выбранную задержку на этом устройстве.
3. Достаточна ли точность Tesseract `rus+eng` на реальных скриншотах MIUI (мелкий шрифт, субпиксельный
   рендеринг, тёмная тема).
4. Какой `psm` и нужен ли upscale для типичных областей — определяется замерами.
5. Ведёт ли себя прозрачная Activity одинаково в MIUI с включённым и выключенным «Центром управления».
6. Есть ли на устройстве дополнительный экран/индикатор приватности при старте захвата.
7. Успевает ли приложение вернуть пользователя в тот же экран исходного приложения, если система
   выгрузила его из памяти (гарантировать это невозможно).

## 12. Правила ведения проекта

1. После каждого завершённого этапа проверять фактические изменения и результаты проверок.
2. Обновлять `PROJECT_STATUS.md` и отмечать критерии выполненными **только при наличии доказательств**.
3. Сохранять работу небольшими логичными коммитами, если пользователь не попросил иначе.
4. Перед коммитом показывать список файлов и краткий diff; не включать секреты и локальные файлы
   (`local.properties`, keystore, build/).
5. После обрыва сессии начинать с чтения `PROJECT_STATUS.md` и `IMPLEMENTATION_PLAN.md`, проверки
   `git status`/`git log` и фактических файлов.
6. Документы не заменяют коммиты и не доказывают сборку или работоспособность.
